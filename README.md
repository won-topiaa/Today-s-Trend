# 🧭 오늘의 트렌드

**젊은 세대와 가까워지는 첫걸음**

자녀와, 학생과, 젊은 동료와 한마디라도 더 나누고 싶은 40~60대 성인을 위한 트렌드 안내 사이트입니다.
젊은 사람들에게 다가가기 위해 꼭 알아야 할 요즘 트렌드를 쉽고 친절하게 알려 드립니다.

## 주요 기능

| 메뉴 | 설명 |
|------|------|
| 🏠 **홈** | 매일 바뀌는 "오늘의 신조어"와 주요 메뉴 바로가기 |
| 📖 **신조어 사전** | 신조어·줄임말·유행어의 뜻, 예시 대화, 사용 팁. 검색과 난이도·종류 필터 지원. **받은 메시지를 통째로 붙여넣으면 그 안의 신조어를 찾아 주는 문장 해석**과 **★ 내 단어장**(기기에 저장) 포함 |
| 🔥 **요즘 유행** | 음식·카페, 콘텐츠·밈, 놀이·문화, 앱·쇼핑, 패션·뷰티, 건강·생활 분야의 최신 유행. 대화 시작 멘트 포함 |
| 📡 **지금 화제** | 구글 급상승 검색어·애플뮤직 차트·위키백과 조회수로 보는 **실시간** 관심사 |
| 💬 **대화 팁** | **상황별 "바로 쓰는 말걸기 문장"(복사 버튼으로 카카오톡에 바로 붙여넣기)**, 대화 시작하는 법, 피해야 할 대화 습관, 신조어 사용 요령, 디지털 소통 예절 |
| ✏️ **퀴즈** | 신조어·트렌드 상식 퀴즈로 나의 트렌드 감각 확인. **단어장에 저장한 단어로만 자동 출제되는 "내 단어장 복습 퀴즈"** 포함 (3개 이상 저장 시) |

## 트렌드 선정 기준

이 사이트는 트렌드를 **두 층**으로 나눠 보여 줍니다.

### 1. 편집형 트렌드 (신조어 사전 · 요즘 유행)

사람이 다음 다섯 가지 기준을 **모두** 충족하는 것만 선별해 설명을 붙입니다.

| 기준 | 내용 |
|------|------|
| **확산성** | 한 커뮤니티를 넘어 여러 플랫폼(유튜브·인스타그램·커뮤니티 등)에서 확인될 것 |
| **지속성** | 최소 한 달 이상 유행이 이어질 것 — 하루짜리 이슈성 밈은 제외 |
| **세대 대표성** | 10~20대가 주도하는 유행일 것 — 전 연령 공통 이슈는 제외 |
| **대화 활용성** | 중장년이 실제 대화 소재로 쓸 수 있을 것 |
| **적절성** | 혐오·차별·정치·사행성·성적 내용은 담지 않을 것 |

각 항목에는 유행 시기(`era`)를 정직하게 표기해, 이미 정점을 지난 표현인지 알 수 있게 합니다.

### 2. 실시간 화제 (지금 화제)

기계가 자동 수집하는 **정량 지표**입니다. API 키 없이 쓸 수 있는 공개 데이터만 사용합니다.

| 출처 | 지표 | 의미 |
|------|------|------|
| 구글 트렌드 급상승 검색어 (KR) | 검색량 급증 | 지금 무엇이 화제인가 (화제성) |
| 애플뮤직 인기곡 차트 (KR) | 재생 수 상위 | 젊은 층이 실제 소비하는 음악 (문화 소비) |
| 한국어 위키백과 조회수 상위 | 문서 조회수 | 사람들이 찾아본 인물·작품·사건 (관심 검증) |

두 층의 역할 구분: **실시간 지표는 "무엇이" 화제인지만 보여 주고, 그것이 무엇이며 어떻게 대화에 쓰는지는 편집형 콘텐츠가 설명합니다.** 이 구분은 화면에도 그대로 안내되어 있습니다.

## 실시간 데이터 구조

```
GitHub Actions (6시간마다)                    사용자 브라우저
┌─────────────────────────┐          ┌──────────────────────────────┐
│ scripts/fetch-trends.mjs │          │ js/live.js                   │
│  ├ 구글 트렌드 RSS        │          │  ├ 애플뮤직·위키백과는        │
│  ├ 애플뮤직 RSS          │─commit─▶ │  │  공개 API로 직접 실시간 조회 │
│  └ 위키백과 통계 API      │          │  └ 실패 시·구글 검색어는       │
│ → data/live-trends.json │          │     live-trends.json 사용     │
└─────────────────────────┘          └──────────────────────────────┘
```

- **이중 안전망**: 브라우저 직접 조회(가장 실시간)가 실패하면 GitHub Actions가 수집해 둔 파일로 대체하고, 그마저 없으면 친절한 안내 문구를 보여 줍니다. 일부 피드가 죽어도 화면이 깨지지 않습니다.
- 수집 스크립트는 피드 일부가 실패하면 **이전 데이터를 유지**하며, Actions 탭에서 "Run workflow"로 수동 실행할 수도 있습니다.

> **GitHub Pages 배포 시 확인할 점**: GitHub 문서상 `GITHUB_TOKEN`으로 push된 커밋은 "Deploy from a branch" 방식의 Pages 빌드를 트리거하지 않을 수 있습니다(실제로는 배포되는 사례도 많아 저장소마다 다릅니다). 첫 자동 수집 커밋 후 Actions 탭에 `pages build and deployment` 실행이 생기는지 한 번 확인해 주세요. 생기지 않으면 ① Pages 소스를 "GitHub Actions"로 바꾸거나 ② 워크플로에 개인 액세스 토큰(PAT)을 써서 push하도록 바꾸면 됩니다. 이 경우에도 애플뮤직·위키백과 카드는 브라우저가 직접 불러오므로 항상 최신입니다.

## 중장년층을 배려한 설계

- **글자 크기 조절**: 화면 위 "보통 / 크게 / 아주 크게" 버튼으로 언제든 조절 (선택은 자동 저장)
- **큰 글씨와 높은 대비**: 기본 글자 크기 18px 이상, 읽기 편한 색 대비
- **단순한 화면 구성**: 다섯 개의 큰 메뉴, 한 화면에 한 가지 내용
- **키보드·스크린리더 접근성**: 건너뛰기 링크, 명확한 초점 표시, 의미 있는 마크업

## 실행 방법

별도의 설치나 서버 없이 동작하는 정적 웹사이트입니다.

- `index.html` 파일을 브라우저에서 열면 바로 사용할 수 있습니다.
- 또는 간단한 웹 서버로 실행할 수 있습니다:

```bash
# 파이썬이 있는 경우
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

### GitHub Pages로 배포하기

1. GitHub 저장소의 **Settings → Pages**로 이동
2. **Source**를 `Deploy from a branch`로 선택
3. 배포할 브랜치와 `/ (root)` 폴더를 선택하고 저장
4. 잠시 후 발급되는 주소로 누구나 접속할 수 있습니다

## 프로젝트 구조

```
├── index.html          # 단일 페이지 (모든 화면 포함)
├── css/
│   └── style.css       # 스타일 (글자 크기 3단계 지원)
├── js/
│   ├── app.js          # 화면 전환·검색·필터·퀴즈 로직 (외부 라이브러리 없음)
│   ├── live.js         # "지금 화제" 실시간 데이터 불러오기
│   └── data/
│       ├── meta.js         # 사이트 기준일 등 공통 정보
│       ├── slang-data.js   # 신조어 사전 데이터
│       ├── trends-data.js  # 요즘 유행 데이터
│       ├── guide-data.js   # 대화 팁 데이터
│       ├── starters-data.js # 상황별 말걸기 문장 데이터
│       └── quiz-data.js    # 퀴즈 데이터
├── data/
│   └── live-trends.json    # 실시간 화제 데이터 (GitHub Actions가 자동 갱신)
├── scripts/
│   └── fetch-trends.mjs    # 실시간 데이터 수집 스크립트 (Node 20+, 의존성 없음)
├── .github/workflows/
│   └── update-trends.yml   # 6시간마다 수집을 실행하는 GitHub Actions
└── README.md
```

## 콘텐츠 업데이트

트렌드는 빠르게 바뀝니다. `js/data/` 폴더의 데이터 파일만 수정하면 화면에 바로 반영됩니다.
새 항목을 추가할 때는 각 파일 안의 기존 항목 형식을 그대로 따라 작성하면 됩니다.
데이터를 갱신한 뒤에는 `js/data/meta.js`의 기준일도 함께 바꿔 주세요.
